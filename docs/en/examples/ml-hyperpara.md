# ML Hyperparameter Search

End-to-end walkthrough of [`examples/applications/ml_hyperpara_benchmark/`](https://github.com/Optima-CityU/LLM4AD_Next/tree/main/examples/applications/ml_hyperpara_benchmark). The task is to evolve a hyperparameter-tuning routine for an ML pipeline that maximizes test accuracy on a benchmark dataset within a fixed compute budget.

This example shows how LLM4AD scales beyond classic algorithm design into **AutoML-style search**: the EVOLVE block is a tuning function rather than a sorting routine, but the pipeline (Island GA, evaluator, EVOLVE markers) is unchanged.

## What evolves

The EVOLVE block lives in `tuner_algorithm/`:

```python
# EVOLVE_START
def tune(model_factory, X_train, y_train, X_val, y_val, time_budget_s):
    """Return (fitted_model, val_accuracy).

    Free to call model_factory(**hparams) any number of times,
    as long as the total wall time stays under time_budget_s.
    """
    pass
# EVOLVE_END
```

The evaluator runs this against several `(model_factory, dataset)` instances and aggregates validation accuracy.

## How to run

```bash
cd LLM4AD
uv sync --extra eval                  # pandas, numpy, scipy
export LLM_BASE_URL="https://api.openai.com/v1"
export LLM_API_KEY="sk-..."
export LLM_MODEL="gpt-4o-mini"

llm4ad run examples/applications/ml_hyperpara_benchmark/config.yaml
```

End-of-run output (abridged):

```text
[bold green]Pipeline completed successfully![/bold green] Best score: 0.8753
Best algorithm worktree: tuner_algorithm-...
Best snapshot: runs/ml_hyperpara_benchmark/<run_id>/best
```

`score` is the mean validation accuracy across all dataset instances.

## Evaluator walkthrough

The evaluator wraps each instance in a `BenchmarkEvaluator.evaluate_instance`:

1. Loads `(X_train, y_train, X_val, y_val)` from a `.npz` file under `data/`.
2. Loads the model factory referenced by the instance metadata (e.g. `RandomForestClassifier` from scikit-learn).
3. Calls the candidate `tune(...)` with a strict per-instance `time_budget_s` (the framework also enforces `evaluator.timeout`).
4. Records:
   - `val_accuracy` — primary score
   - `time_used_s` — clock time
   - `n_evaluations` — how many candidates the tuner tried internally
5. Returns `EvaluationResult(score=val_accuracy, metrics={...})`.

`aggregate(...)` reports the mean of `val_accuracy` and the sum of `time_used_s` across instances.

## A sister example

[`ml_feature_benchmark/`](https://github.com/Optima-CityU/LLM4AD_Next/tree/main/examples/applications/ml_feature_benchmark) is structured the same way but evolves a **feature-selection** routine instead of a tuner. Useful when accuracy is bottlenecked by feature engineering rather than hyperparameters.

## Variations to try

- **Multi-objective with MEoH**: list `objective_metrics: ["val_accuracy", "time_used_s"]` to evolve a Pareto front of "accurate" vs. "fast" tuners — directly useful when deployed under time budgets.
- **Different model factory**: swap `RandomForestClassifier` for `GradientBoostingClassifier` or a small MLP. The evaluator stays the same.
- **Real datasets**: drop `data/` files generated by `generate_data.py` and use OpenML or your own datasets serialized as `.npz`.
